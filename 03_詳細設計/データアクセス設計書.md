## 1. リポジトリ構成（Spring Data JPA）DD-DAO-01

`interface` を宣言するだけで Spring が実装を生成する（SQL を書かずに CRUD＋派生クエリ）。

```java
public interface ArticleRepository extends JpaRepository<Article, Long> {
    boolean existsByUrlHash(String urlHash);          // SELECT 1 ... WHERE url_hash=?
    // 複雑な整列/検索は JPQL か、必要なら jOOQ を局所併用
    @Query("""
        select a from Article a
        where (:category is null or a.category = :category)
        order by coalesce(a.eventDate, cast(a.createdAt as date)) desc
    """)
    Page<Article> searchTimeline(@Param("category") Category c, Pageable p);
}
```

| リポジトリ | 主メソッド | 対応 |
|---|---|---|
| `ArticleRepository`（DD-DAO-02） | `existsByUrlHash` / `searchTimeline` / pg_trgm 検索 | FR-02-08・FR-04 |
| `ArticleThemeMatchRepository` | 複合キー保存 | FR-02-10 |
| `ArticleNotificationRepository`（DD-DAO-03） | 未通知抽出（NOT EXISTS）/ upsert | FR-03-01/06 |
| `NotificationLogRepository` | 当月通数 `SUM`（JST月） | FR-03-05 |
| `LlmUsageLogRepository` | 当月コスト `SUM`（JST月） | FR-06-06 |
| `SourceRepository` | `findByIsActiveTrueAndTermsReviewedTrue` | FR-02-12 |
| `ThemeRepository`/`UserRepository`/`Favorite*`/`ReadStateRepository`/`BookmarkRepository`/`CrawlLogRepository` | 各CRUD | §6 |

> **派生クエリ vs JPQL vs jOOQ（DD-DAO-04）**: 単純条件は**メソッド名から自動生成**（`existsByUrlHash`）。整列/期間/種別が絡む一覧は **JPQL**（型安全・可読）。pg_trgm や式インデックスを効かせたい部分は必要に応じ**ネイティブSQL/jOOQ を局所併用**。全文検索は `WHERE title % :q`（pg_trgm）。

## 2. 冪等性の実装（DB制約＋握り）DD-DAO-05

### 2.1 記事の重複登録防止

```java
try {
    articleRepository.save(article);      // INSERT
    articleRepository.flush();            // ここで UNIQUE(url_hash) 違反が飛ぶ
} catch (DataIntegrityViolationException e) {
    // 別実行が同時に入れた等。正常系として握り、新規扱いしない（BD-BATCH-C-06）
    return SaveOutcome.DUPLICATE;
}
```

- 事前 `existsByUrlHash` は**一次判定**（無駄な処理を省く）、**UNIQUE 制約が最終防衛線**。`flush()` で違反を早期に受ける。
- URL 正規化→ハッシュは `UrlNormalizer`/`UrlHasher`（DD-CLS-20/21）で決定的に生成。

### 2.2 通知の冪等（DD-DAO-06）

- **未通知＝`article_notifications` に `(user_id, article_id)` 行が無い**。抽出は `NOT EXISTS`。
- 成功で `INSERT (result=Delivered)`、打ち切りで `INSERT (result=GaveUp)`。複合PKにより二重INSERTは制約で弾く。
- 同日2回目は `users.last_notified_at` を **JST 日付**で比較して抑止（DD-DAO-08 の時刻方針）。

## 3. UTC 保存・JST 変換の実装（DD-DAO-07 / NFR-08）

| 層 | 型 | 扱い |
|---|---|---|
| DB | `timestamptz` | UTC で格納（`event_date` のみ `date`） |
| エンティティ | `Instant`（DD-DAO-08） | 常に UTC。`LocalDateTime` は使わない（ゾーン欠落の事故を防ぐ） |
| 集計（当月/同日） | JST に変換して境界決定 | `at = instant.atZone(TZ)`、`TZ = ZoneId.of("Asia/Tokyo")` を**定数1箇所**に集約 |
| 表示 | `JstFormatter`（DD-CLS-24） | 表示直前に JST の `ZonedDateTime`／文字列へ |

```java
public final class TimeZones {           // ゾーンIDの散在禁止（NFR-08）
    public static final ZoneId JST = ZoneId.of("Asia/Tokyo");
    private TimeZones() {}
}
```

> 「同日」「当月」は**JST の暦**で判定する必要がある（利用者は日本時間で使う）。DB/エンティティは UTC のまま、境界計算と表示でのみ JST に変換する。

## 4. enum の永続化（AttributeConverter）DD-DAO-09

`@Enumerated(ORDINAL)`（列挙順に暗黙依存＝並べ替えで壊れる）を**使わない**。コード値を明示変換する。

```java
@Converter(autoApply = false)
public class CategoryConverter implements AttributeConverter<Category, Short> {
    public Short convertToDatabaseColumn(Category c){ return c == null ? null : c.code(); }
    public Category convertToEntityAttribute(Short db){ return Category.fromCode(db); }
}
```

- `Category`/`EventDatePrecision`/`EventDateKind`/`FetchType`/`CrawlStatus`/`LlmCallStatus`/`UserRole`/`NotifyStatus` それぞれに Converter。enum は `code()` と `fromCode()` を持つ（テーブル定義書 §0 の smallint コード値と一致）。
- 将来カテゴリ追加は enum にコードを足すだけ（スキーマ変更不要）。

## 5. トランザクション境界（DD-DAO-10）

| 処理 | 境界 | 理由 |
|---|---|---|
| 収集：1記事の登録＋マッチ保存 | `@Transactional`（記事単位・短く） | 途中失敗のロールバックを記事単位に閉じ、他記事に波及させない |
| 収集：情報源ループ | **各記事でコミット**（ループ全体を1トランザクションにしない） | 1情報源で大量取得しても長時間ロックを避け、失敗分離と両立 |
| 通知：1利用者の送信＋記録 | 送信成功後に `Delivered`＋通数＋`last_notified_at` を1トランザクション | 「送ったのに未記録」を避け冪等を保つ。送信は外部呼び出しのためトランザクション内で最小限に |
| 一覧表示 | 読み取り専用（`@Transactional(readOnly=true)`）＋DTO詰め替え | `LazyInitializationException` を避け、表示は DTO に閉じる |

> **N+1 対策（DD-DAO-11）**: 一覧で情報源名等が要るなら `join fetch` かプロジェクション（DTO直射影）で1クエリにまとめる。遅延ロードのままViewへ渡さない。

## 6. Flyway マイグレーション（DD-DAO-12）

- `V1__init.sql`：拡張（`CREATE EXTENSION IF NOT EXISTS pg_trgm;`）＋全テーブル DDL＋制約＋インデックス（式インデックス `((COALESCE(event_date, created_at::date)))`・GIN trgm 含む）＋seed（初期利用者・第一陣情報源で `terms_reviewed=false`）。
- 以降の変更は `V2__*.sql`, `V3__*.sql` と**追記**（既存を書き換えない）。テーブル定義書＝マイグレーションの正。
- Hibernate の `ddl-auto` は **`validate`**（自動生成させず Flyway に一本化・スキーマの正を1つにする）。
