1. 設定の分類（機密 / 非機密）DD-CFG-01

種別 例 注入方法
機密 Claude APIキー／LINE チャネルアクセストークン／DBパスワード 環境変数のみ（application.yml はプレースホルダ ${...}）。ローカル=.env、VPS=systemd EnvironmentFile
非機密の環境差分 DBホスト・ログレベル・User-Agent 連絡先・モデル単価・タイムアウト・上限値 Spring Profiles（application-{profile}.yml）で切替
不変の定数 ZoneId（Asia/Tokyo）・enum コード コード（定数）に集約

2. application.yml の構造（DD-CFG-02）

spring:
  datasource:
    url: ${DB_URL}                 # 例 jdbc:postgresql://localhost:5432/aggregator
    username: ${DB_USER}
    password: ${DB_PASSWORD}       # 実値は環境変数。ここには書かない
  jpa:
    hibernate:
      ddl-auto: validate           # スキーマは Flyway に一本化（DD-DAO-12）
  flyway:
    enabled: true

app:
  user-agent: ${APP_USER_AGENT:Aggregator/1.0 (contact: you@example.com)}  # 非機密・既定値可
  llm:
    model: ${LLM_MODEL:claude-sonnet}      # 実モデルID/単価は着手時に確認
    monthly-cap-jpy: 500
    safety-margin: 0.9
    price:                                  # 非機密・モデル別単価（着手時に確認）
      input-per-1k: ${LLM_PRICE_IN:0}
      output-per-1k: ${LLM_PRICE_OUT:0}
  line:
    channel-access-token: ${LINE_CHANNEL_TOKEN}   # 機密・環境変数
    monthly-message-cap: 200
    carousel-bubble-limit: 12                       # 着手時に公式確認
  anthropic:
    api-key: ${ANTHROPIC_API_KEY}                   # 機密・環境変数
  • 機密は必ず ${...} で外部化。既定値を付けない（未設定なら起動時に落とし、事故的にデフォルトで動くのを防ぐ）。
  • 非機密は ${VAR:default} で既定値可。

3. プロファイル（DD-CFG-03）

プロファイル 用途 差分例
local 自宅PC開発 DBホスト=localhost、ログ=DEBUG、Docker Compose の PostgreSQL
prod VPS（Phase 6） DBホスト=本番、ログ=INFO、Docker 化

起動アプリ別（web/collection/notification）は §DI設計書 §4 のスキャン範囲で分離。プロファイルは環境差分のみを担い、機密は持たない。

4. ローカルの秘密情報：.env（DD-CFG-04）

  • .env は .gitignore に必ず登録（コミット禁止）。中身は KEY=VALUE。
  • リポジトリには .env.example（キー名のみ・値は空/ダミー）を置き、必要な環境変数を明示。
# .env.example（コミットする・値は入れない）
DB_URL=
DB_USER=
DB_PASSWORD=
ANTHROPIC_API_KEY=
LINE_CHANNEL_TOKEN=
APP_USER_AGENT=
  • 読み込みは起動スクリプト/IDE のEnvFile、または spring-dotenv 等（採用可否は着手時に判断）。アプリコードは環境変数しか見ない（.env はそれを流し込む手段）。

5. VPS（Phase 6）での注入（DD-CFG-05）

  • systemd EnvironmentFile=/etc/aggregator/secret.env（パーミッション 600）で環境変数を注入、または docker compose の env_file。
  • OS 依存の資格情報ストアは使わない（NFR-09 移行性に反する）。
  • 秘密情報のローテーションは環境変数の差し替えのみで完結（再ビルド不要）。

6. 秘密情報を漏らさないための実装ルール（DD-CFG-06）

  • ログ・例外メッセージ・画面にトークン/キーを出さない（マスクする）。
  • 設定値の読み取りは @ConfigurationProperties（型安全なバインド）または @Value。生の環境変数参照をコード全体に散らさない。
  • テストではダミー値を使い、実キーをテストコード/CI に置かない。
