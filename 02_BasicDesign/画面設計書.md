## 0. 全画面に共通する設計方針（★決定事項）

要件定義の承認を受け、外部設計の基盤方針を以下で確定する。

| ID | 方針 | 決定内容 | 根拠 |
|---|---|---|---|
| BD-SC-00-01 | ナビゲーション構造 | **Vaadin `AppLayout`（上部バー＋左ドロワー）**。上部バー＝アプリ名／現在の利用者名／ログアウト。左ドロワー＝メニュー（折りたたみ可）。管理系メニューは admin のみ表示 | FR-07-04・SC全体 |
| BD-SC-00-02 | 一覧の見せ方 | **カード型リスト**（1記事＝1カード）。要約中心で可読性を優先し、権利配慮（画像非表示）と両立 | FR-04・§9 |
| BD-SC-00-03 | ページング | **ページ送り方式**（既定20件/ページ）。総件数・ページ番号を表示。無限スクロールは採らない（件数把握・NFR-04 と相性） | FR-04-01・NFR-04 |
| BD-SC-00-04 | 日時表示 | すべて **JST 表示**（UTC保存→表示直前に `Asia/Tokyo` 変換）。日付は「YYYY/MM/DD」、日時は「YYYY/MM/DD HH:mm」 | NFR-08 |
| BD-SC-00-05 | 権利配慮 | 画面に出すのは **自作要約＋メタ情報＋元URL のみ**。記事本文・公式画像・ロゴ/ビジュアルは表示しない | §9 |
| BD-SC-00-06 | ロール出し分け | 管理系画面/ブロックは Spring Security（`@PreAuthorize` 等）でサーバー側制御。メニュー非表示だけに頼らず、画面到達も拒否 | FR-07-04・NFR-02 |
| BD-SC-00-07 | 発生日の表示 | 日付は**種別ラベル付き**（例「発売日 9/20」「開催日 10/1」）。精度が粗い場合は原文を併記（例「発売日 9月（9月中旬）」） | FR-04-01・EventDateKind/Precision |
| BD-SC-00-08 | レスポンシブ | 自宅PCブラウザを主・協力者のモバイル確認を従とし、幅が狭い時は左ドロワーを自動折りたたみ、カードを1列化 | 成功基準③（協力者テスト） |
| BD-SC-00-09 | UIデザイン方針 | **Vaadin 標準の Lumo をカスタムテーマで作り込む**方式を採用（プラグインを盛らない）。`frontend/themes/aggregator/styles.css` で Lumo の CSS カスタムプロパティ（`--lumo-primary-color`／`--lumo-border-radius`／フォント／余白）を上書きし、ダーク対応は `Lumo.DARK` バリアントで実現。デザイントークンは §0.1 に定義。図表（LLMコスト/通数）は商用の Vaadin Charts を避け、**無料の add-on（ApexCharts.js／Chart.js）または Lumo の ProgressBar** で表現。アイコンは Vaadin Icons（内蔵）。フォントは self-host（CDN 非依存＝オフライン/VPS/権利配慮）。理由＝Java/Vaadin 初学＋ポートフォリオでは、標準の完成度を活かし依存を最小化する方が保守性・説明可能性が高い（CLAUDE.md §2-3・§0-4） | Q29・D5 |

### 0.1 デザイントークン（Lumo カスタムテーマの上書き値・実装時の指針）

モックアップ（`画面モックアップ.html`）で見た目を確定し、実装では下表を `styles.css` の Lumo プロパティに落とし込む。**値は目安**（実装着手時に微調整）。

**テーマ名: 「和ノスタルジック（水彩・自然/黄昏）」**（Q30）。穏やかで温かい和風の空気感を狙う。**特定の作品のロゴ・キャラクター・公式カラーを流用せず、あくまでムード（配色・質感）としてのオリジナルテーマ**（§9 権利配慮・ロゴ/ビジュアル不使用と整合）。

| 種別 | トークン（モック→Lumo対応） | 値（ライト） | 備考 |
|---|---|---|---|
| 基調背景 | `--bg` | `#f4efe1`（和紙クリーム） | 温かみのある淡いベージュ |
| パネル/カード | `--lumo-base-color` | `#fffdf6` | 生成り |
| プライマリ | `--lumo-primary-color` | `#5f8768`（苔・若葉の緑） | ボタン/リンク/アクティブ。グラデ `#5f8768→#8caf76` を強調用に |
| 文字 | `--lumo-body-text-color` | `#39322a`（墨茶） | 温かい焦茶 |
| 補助文字 | `--lumo-secondary-text-color` | `#8c7f68` | |
| 見出し書体 | （独自 `--serif`） | 明朝系（Hiragino Mincho/Yu Mincho/Noto Serif JP） | 文学的・ノスタルジックな余韻。本文はゴシック |
| 上部バー | `--topbar1/2` | `#3c4a44→#4e4a60`（黄昏の緑→藍） | 夕暮れ・自然のグラデ |
| 角丸 | `--lumo-border-radius-l/m/s` | 16 / 12 / 8 px | 大きめの角丸で柔らかく |
| 影 | `--lumo-box-shadow-*` | 2段の暖色寄りの淡い影 | 立体感は控えめ・上品に |
| カテゴリ色 | （独自） | 全体を**やや彩度を落とした earthy 系**に統一（青/紫/桃/橙/緑/藍/赤茶/灰） | chip で色分け（可読性優先） |
| フォント（本文） | `--lumo-font-family` | Noto Sans JP＋Inter（self-host） | 日本語対応・CDN非依存 |
| 地紋（和柄） | （独自 `--wa`） | **七宝つなぎ（重ね円）**を淡く敷く | 伝統文様（非著作物）。CSS の重ねグラデ or 軽量 SVG で実装。背景/上部バー/ログインに低透過で。可読性優先で控えめに |
| ダーク | `Lumo.DARK` バリアント | 暖色の暗色一式（焦茶ベース） | OS/切替に追従 |

> 実装での実現も §BD-SC-00-09 と同じ：Lumo の CSS カスタムプロパティを上書きするだけで全コンポーネントに一貫適用（プラグイン不要）。明朝の見出しは self-host した Noto Serif JP を `--serif` 相当のクラスに割り当てる。

### 0.2 画面イメージ（モックアップ）

本書の**視覚的リファレンスは [`画面モックアップ.html`](画面モックアップ.html)**（自己完結の静的HTML）。配色・和柄・余白・カード/チップ/ボタンの質感・遷移の雰囲気はこのモックで確定済みとする。**Vaadin 実装ではなく、見た目合わせのためのプロトタイプ**（データはサンプル）。

モックが体現している確定事項（本書の各節と対応）:

| 観点 | モックでの表現 | 対応 |
|---|---|---|
| ナビゲーション | 上部バー（アプリ名・利用者名・ログアウトのみ／ロール切替UIは無し）＋左ドロワー | BD-SC-00-01 |
| ロール出し分け | 管理系（情報源マスタ/ダッシュボード/実行ログ/利用者管理）は admin ログイン時のみドロワー表示、user は非表示＋到達拒否画面 | BD-SC-00-06・SC-06〜09 |
| 一覧 | カード型・種別ラベル付き日付・未読ドット・未通知バッジ・画像非表示枠・並び順/フィルタ/ページャ | SC-02 |
| 元記事リンク | 「元記事を開く」は**新規タブ**で外部サイトへ（`target="_blank" rel="noopener"`）。タイトルは記事詳細(SC-03)へ | BD-SC-02-08・FR-04-05 |
| ログイン | 利用者一覧クリック＋管理者PINパッド＋「新規登録（誰でも）」導線 | SC-01・SC-10 |
| デザイン | 和ノスタルジック配色＋七宝の地紋＋明朝見出し＋ダーク対応 | BD-SC-00-09・§0.1 |

> モックの操作: ログイン→利用者クリック（管理者はPIN）→アプリ。管理系は「管理者アカウント」でログインすると出る。OSのダーク設定で暖色ダークに追従。

```

│ 〔管理〕(admin) │                                  │
│ ● 情報源マスタ   │                                  │
│ ● 管理ダッシュ   │                                  │
│ ● 実行ログ      │                                  │
```

- ドロワー上段（共通）: タイムライン(SC-02) / テーマ管理(SC-04) / **LINE通知設定(SC-05)**

- **新規アカウント登録(SC-10)はドロワーに置かない**。ログイン画面(SC-01)の「新規登録」入口から遷移（誰でも・PIN不要・Q27）。**利用者登録・管理(SC-09)は管理者ログイン後にドロワー「管理」グループから利用**（Q28。管理者はログイン時にPINを通すため管理機能はアプリ内に配置）。

## SC-01 ログイン（利用者選択＋管理者PIN）

| 属性 | 内容 |
|---|---|
| アクセス | 未認証 |
| 関連機能 | FR-07-01, FR-07-02 |
| データ | `users`（is_active 相当＝有効な利用者の id/display_name/role/admin_pin_hash） |

### レイアウト・項目

- 中央にカード。見出し「利用者を選択してください」。
- **有効な利用者の一覧**を [表示名（ID）] のクリック可能な行/ボタンで縦に並べる（BD-SC-01-01）。役割アイコンで admin を区別（鍵マーク）。
- パスワード入力欄は**無し**。
- カード下部に **「＋ 新規登録」リンク**（BD-SC-01-07・誰でも・PIN不要→SC-10）。※利用者の編集・削除・Admin付与は管理者ログイン後のドロワー（SC-09）で行うため、ログイン画面には管理入口を置かない（Q28）。

### 操作・入出力

| ID | 操作 | 挙動 |
|---|---|---|
| BD-SC-01-02 | 一般利用者(role=User)を選択 | クレデンシャル入力なしでセッション確立→タイムライン(SC-02)へ |
| BD-SC-01-03 | 管理者(role=Admin)を選択 | **4桁PIN入力ダイアログ**を開く。数字4桁のみ受付 |
| BD-SC-01-04 | PIN送信 | `admin_pin_hash`(BCrypt) と照合。一致でセッション確立→SC-02。不一致はダイアログにエラー表示（MSG参照） |
| BD-SC-01-05 | PIN連続失敗 | **5回失敗で当該管理者を数分ロック**（総当たり抑止）。ロック中は選択不可＋残り時間表示 |
| BD-SC-01-07 | 「新規登録」を押下 | **PIN不要**で **新規アカウント登録(SC-10)へ遷移**。誰でも自分を role=User で登録できる（Q27） |

> セキュリティ注記: 4桁PINは低エントロピーのため、ロック＋ハッシュ保存で最低限の防御。VPS移行(Phase 6)で全利用者をパスワード/OAuth 認証へ差し替える（`role` は流用）。

## SC-02 タイムライン（一覧）★中心画面

| 属性 | 内容 |
|---|---|
| アクセス | 共通（user/admin） |
| 関連機能 | FR-04-01〜06 |
| データ | `articles` ×（ログイン利用者の `themes`／`read_states`／`article_notifications`／`bookmarks`） |

### レイアウト（上→下）

1. **ツールバー（BD-SC-02-01）**
   - 並び順セレクト: ①発生日順（既定）／②発売日順／③収集日順（BD-SC-02-02）
   - 昇順/降順トグル（BD-SC-02-03）
   - 検索ボックス（タイトル・要約の部分一致・pg_trgm）（BD-SC-02-04）
2. **フィルタ行（BD-SC-02-05）**: テーマ / カテゴリ / 期間（From-To）/ 未読 / **未通知** / **発生日種別**（発売日・開催日・放送日…）。複数指定は AND。
3. **記事カードリスト（BD-SC-02-06・カード型）**: 1記事＝1カード。
4. **ページャ（BD-SC-02-07）**: 前/次・ページ番号・総件数（既定20件/ページ）。

### 記事カードの表示要素（BD-SC-02-08）

| 要素 | 内容 | 備考 |
|---|---|---|
| タイトル | 記事見出し（クリックで SC-03 記事詳細へ） | 本文は出さない |
| 日付 | **種別ラベル付き**（例「発売日 9/20」）。精度が粗ければ原文併記 | BD-SC-00-07 |
| カテゴリ | カテゴリchip（グッズ/アニメ…） | Category enum |
| 情報源 | 情報源名 | Sources.name |
| 要約 | 自作要約（2〜3行で省略表示） | 本文転載しない（§9） |
| 既読/未読 | 未読は強調（太字/未読ドット）。カード開封で既読化（FR-04-04） | read_states |
| 未通知バッジ | LINE未達（失敗/上限/打ち切り）の記事に「未通知」バッジ（FR-04-06） | article_notifications=GaveUp 等 |
| ブックマーク | ☆トグル（後で見る・通知対象外） | bookmarks（FR-05-03） |
| 元記事リンク | 「元記事を開く」外部リンク（新規タブ） | url（FR-04-05） |

### 操作・整列ルール

| ID | 操作 | 挙動 |
|---|---|---|
| BD-SC-02-09 | 発生日順 | 全種別横断で `COALESCE(event_date, created_at::date)`。NULLは収集日代理で新着上位 |
| BD-SC-02-10 | 発売日順 | `event_date_kind=発売日(1)` の記事を `event_date` で整列（昇順で近い発売が上位） |
| BD-SC-02-11 | 収集日順 | `created_at` で整列 |
| BD-SC-02-12 | 未読既読切替 | カード上のトグル or 開封で `read_states` 更新 |
| BD-SC-02-13 | 画像非表示の明示 | サムネイル枠を置かない（権利配慮・§9）。視認性はカテゴリchip＋種別ラベルで補う |

> パフォーマンス: 整列・絞り込みは式インデックス `ix_articles_timeline` と各索引で担保し一覧応答2秒（NFR-04）。

## SC-05 LINE通知設定（旧「お気に入り管理」）

| 属性 | 内容 |
|---|---|
| アクセス | 共通（各自の分のみ） |
| 関連機能 | FR-05-01〜04, FR-07-03 |
| データ | `users`(自分の line_user_id / notify_enabled) / `favorite_themes` / `favorite_sources` / `bookmarks` |

> **統合の意図（Q26）**: LINE通知に関わる本人設定を1画面に集約する。①LINEに繋ぐ設定（連携・全体ON/OFF）と、②何を通知するか（お気に入り＋通知ON/OFF）は密接なため、同じ画面で完結させる。旧「お気に入り管理」を改称・拡張した。

### レイアウト（上段：LINE連携ブロック＋下段：タブ）

**上段 — 自分のLINE連携（BD-SC-05-05）**（本人が設定）

| ID | 項目 | 内容 |
|---|---|---|
| BD-SC-05-06 | LINEユーザーID | `line_user_id` の登録/更新（手動） |
| BD-SC-05-07 | 通知の全体ON/OFF | `notify_enabled`（マスタスイッチ。OFFで自分への通知を全停止） |
| BD-SC-05-08 | 連携ステータス | 「連携OK／未追加／直近送信失敗」を表示。**未追加・ブロック時は友だち追加案内（QR/リンク）**（③を受信側が自己解決） |

**下段 — お気に入り／ブックマーク（タブ構成・BD-SC-05-01）**

1. **テーマお気に入り**: 自分のテーマ一覧に「お気に入り」トグルと「通知ON/OFF」トグル（BD-SC-05-02）。
2. **情報源お気に入り**: 情報源一覧に同上のトグル（BD-SC-05-03）。
3. **ブックマーク（後で見る）**: ブックマーク済み記事の一覧（SC-03へ遷移可）。**通知対象外**であることを明示（BD-SC-05-04）。

> 通知が届く条件（画面上でも明示）: ①お気に入り登録 ②そのお気に入りの通知ON ③全体通知ON（上段） ④LINE ID登録済 ⑤通数枠あり、をすべて満たすと届く。上段②③④が「LINEに繋ぐ」設定、下段の①②が「何を通知するか」。
> 用語の区別を画面文言でも徹底: 「お気に入り＝通知する／ブックマーク＝後で見るだけ（通知しない）」。

## SC-09 利用者登録・管理（admin・ドロワー「管理」グループ）

| 属性 | 内容 |
|---|---|
| アクセス | **admin のみ**（管理者でログイン後、アプリ本体のドロワー「管理」グループから利用。SC-06〜08 と同列） |
| 関連機能 | FR-07-02 |
| データ | `users` |

### レイアウト・操作

- 見出し「利用者登録・管理」。上部に「＋ 利用者を追加」ボタン→フォーム（BD-SC-09-01）。
- 利用者一覧（Grid）: 表示名 / ロール / 管理者PIN設定状況 / 有効フラグ / 操作（**編集・削除**）（BD-SC-09-02）。
- フォーム項目（BD-SC-09-03）: 表示名（必須）／**ロール**（User/Admin＝**Admin付与**）／**管理者PIN**（Admin時のみ・4桁）／有効フラグ。PINは BCrypt でハッシュ保存（平文保存しない）。
- ここで **編集・削除・Admin付与・PIN設定**を行う。SC-10 の自己登録（User固定）に対し、権限を伴う操作は本画面（admin）に集約。
- 初期2名（admin 1・user 1）は seed 投入。SC-10 で自己登録された利用者もここで編集・ロール変更できる。

> **配置の意図（Q28）**: 管理者はログイン時に4桁PINを通す（SC-01）。その後の利用者管理はアプリ内の管理機能として、他の管理系（SC-06 情報源マスタ／SC-07 ダッシュボード／SC-08 ログ）と同じドロワー「管理」グループに置く。ログイン画面には管理入口を置かない（新規登録=SC-10 のみ）。認可は Spring Security でも担保（非adminのメニュー非表示＋直接到達拒否・BD-SC-00-06）。BD-SC-09-04（ログイン画面へ戻る）は廃止（ドロワー配置のため不要）。

## SC-10 新規アカウント登録（未認証・誰でも）

| 属性 | 内容 |
|---|---|
| アクセス | **未認証（誰でも・PIN不要）**。ログイン画面 SC-01 の「新規登録」から遷移 |
| 関連機能 | FR-07-05 |
| データ | `users`（INSERT・role=User 固定） |

### レイアウト・操作

- 見出し「新規アカウント登録」。中央にシンプルなフォーム。
- フォーム項目（BD-SC-10-01）: **表示名（必須）**のみ。ロールは表示せず **role=User に固定**（Admin は選べない）。管理者PIN欄は**無し**。
- 操作: 「登録する」（BD-SC-10-02）→ `users` に role=User で INSERT →**ログイン画面（SC-01）へ戻り**、登録した利用者が一覧に並ぶ。
- 「‹ ログイン画面へ戻る」（BD-SC-10-03）。

> **設計意図（Q27・open signup / restricted privilege escalation）**: 一般利用者の追加を管理者ボトルネックにしないため、登録の入口を未認証で開放する。ただし**自己登録では Admin ロール付与・管理者PIN設定・他人の編集/削除はできない**（それらは admin の SC-09 のみ）。これにより誰でも登録できても、管理者PINで守る管理系（SC-06〜08）へ自己昇格できない。VPS移行(Phase 6)で本格認証に切替時は、本画面がメール等を伴う正式なサインアップに発展する余地を残す。
