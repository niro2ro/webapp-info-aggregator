## 1. システム概要

アニメ・漫画などのテーマ（キーワード）を登録すると、関連する最新情報（グッズ・イベント・放送・コラボ等）を複数の情報源から自動収集し、発生日順の一覧で確認できる Web アプリケーション。お気に入り登録した対象に新着があれば LINE で通知する。

- 想定利用者: 2名（開発者本人＋協力者1名）
- 実行環境: 自宅 Windows PC（常時稼働しない）。バッチはタスクスケジューラでログオン時に起動。
- 将来: 転職活動開始時に VPS へ移設（Phase 6・実施確定）。
- 本プロジェクトは転職活動用ポートフォリオを兼ねる。

### 運用モデルに由来する前提

- 通知は時刻ベースではなく「PC 起動時に前回以降の新着をまとめて届ける」方式。
- 1日に複数回起動されうるため **冪等性の担保が必須**（重複登録・重複通知をしない、同日2回目以降は通知しない）。

## 6. データ設計（DDL レベル）

PostgreSQL 前提。日時は `timestamptz`（UTC 保存）。列挙型はアプリ側 enum に対応する `smallint`（コード値）で保持し、意味はコメントに明記する（EF Core の enum マッピングを想定）。テーブルIDは `TBL-xxx`。

> 命名は PostgreSQL の慣習に合わせ snake_case を基本とする（EF Core 側でマッピング）。以下は論理定義。物理カラム名・制約名は詳細設計で確定する。

### 列挙値の定義

| enum | 値（コード: 意味） |
|---|---|
| Category | 1:グッズ / 2:アニメ / 3:漫画 / 4:イベント / 5:ゲーム / 6:ゲームセンター / 9:その他 |
| EventDatePrecision | 0:Exact(確定日) / 1:Month(月まで) / 2:Season(季節・曖昧) / 3:Ongoing(受付中/発売中等の期間) / 9:Unknown |
| FetchType | 1:Rss / 2:HtmlParser / 3:Llm |
| CrawlStatus | 0:Success / 1:PartialError / 2:Failed |

> `FavoriteTargetType` は当初ポリモーフィック設計（1テーブルでテーマ/ソース両対応）を想定して置いていたが、参照整合性を DB 制約で担保するため **お気に入りをテーブル分割**（`FavoriteThemes` / `FavoriteSources`）した。分割により列挙型は不要となり廃止。

### 冪等性の担保方法（DB レベル）

| 対象 | 担保 |
|---|---|
| 重複登録 | `Articles.url_hash` の UNIQUE 制約。挿入時の一意制約違反を握って握りつぶす |
| 重複通知 | `ArticleNotifications(user_id, article_id)` の PK |
| 同日2回目の通知抑止 | `Users.last_notified_at` を JST 日付で判定（本日既送なら送信しない） |

> アプリ側のチェックだけに頼らず、DB 制約を最終防衛線とする。

### 参照アクション（ON DELETE）方針

| 親→子 | アクション | 理由 |
|---|---|---|
| Articles → ReadStates / ArticleThemeMatches / ArticleNotifications / Bookmarks | CASCADE | 記事パージ（NFR-05）時に付随データを孤児化させない。※ブックマーク済み記事はそもそもパージ対象外なので通常 Bookmarks は連動しない |
| Users → Themes / Favorite* / Bookmarks / ReadStates / ArticleNotifications | CASCADE | 利用者削除時に個人データを一括除去（VPS移行後の退会想定） |
| Themes → ThemeCategories / ArticleThemeMatches / FavoriteThemes | CASCADE | テーマ削除時にマッチ・お気に入りを整理（FR-01-03 の「関連マッチ切り離し」を DB で担保） |
| Sources → Articles / FavoriteSources / CrawlLogs | RESTRICT | 収集済み記事のある情報源の誤削除を防ぐ（無効化は is_active=false で行う） |

## 7. 外部インターフェース仕様

### 7.1 収集対象（インバウンド取得）

| 情報源 | 取得方式 | RSS URL（着手時に実地確認） | 主なカバー範囲・備考 |
|---|---|---|---|
| MANTANWEB | RSS | `https://mantan-web.jp/rss/mantan.xml`（要確認） | アニメ/漫画/ゲーム/ラノベ。毎日新聞系の一次メディア |
| HOBBY Watch | RSS | インプレス系（正確なURLを着手時に特定） | フィギュア/グッズ/**プライズ（メーカー別：タイトー・セガ 等）**。グッズ・ゲームセンターの主軸 |
| Gamer | RSS | 着手時に特定（運営イード＝アニメ！アニメ！/インサイドと同基盤） | **アーケード・ゲームセンター**筐体・ロケテ・イベント/ゲーム |

> **検証に関する注記**: 本要件定義時点では、実行環境のネットワークポリシーにより外部ホストへの HTTP アクセスが全て 403 で拒否され、上記 RSS の生死・robots.txt・利用規約を実地検証できていない。上記は WebSearch（二次情報）にもとづく暫定であり、**Phase 1 着手時に実地確認する**こと（RSS URL 特定・robots 尊重可否・規約上の可否）。使えない場合は控え候補（電撃ホビーウェブ／アニメージュプラス／アキバ総研 等）へ差し替える。

共通ルール: robots.txt 尊重、同一ホスト間隔1秒以上、User-Agent に連絡先を含める。RSS で不足する項目（要約・場所・発生日）は本文抽出→専用パーサー→LLM の順で補完。

将来Phase再検討（今回は不採用）:
- タイトー/セガ/バンダイナムコ等 ゲームセンター公式のプライズ告知（RSS無し＋JS動的描画。一次情報だが専用パーサー＋規約確認前提。当面は HOBBY Watch 経由で代替）
- コミックナタリー（CDNがbotを遮断の疑い。採用時は規約確認＋許諾前提）
- アニメイトタイムズ（公式RSS無し。専用パーサー実装＋規約確認前提）

### 7.2 Claude API（構造化・収集時のみ）

- 入力: 本文抽出テキスト（＋ページのタイトル/URL）
- 出力（JSON 構造化を要求）:
  - `title`（string）
  - `category`（Category enum のいずれか）
  - `event_date`（date or null）
  - `event_date_text`（string or null）
  - `event_date_precision`（EventDatePrecision）
  - `location`（string or null）
  - `summary`（自作要約・本文転載しない）
- モデルID・リクエスト形式は実装着手時に公式ドキュメントで確認する。
- 抽象化（`ILlmStructurer` 等のインターフェース）を挟み差し替え可能にする。

### 7.3 LINE Messaging API（通知・アウトバウンド）

- 方式: push（友だち追加済みユーザーへ）、Flex Message カルーセルで複数件を1吹き出しに集約。
- 通数カウント: 「送信先ユーザー数 × 吹き出し数」。無料枠（コミュニケーションプラン）は月200通前提。上限接近時は送信停止しアプリ内表示に切替。
- 認証: チャネルアクセストークンは User Secrets / 環境変数（直書き禁止）。
- 料金プラン・仕様は改定されるため実装着手時に公式ドキュメントを確認する。LINE Notify は 2025-03-31 終了済みのため Notify 前提記事は参照しない。

## 8. エラーハンドリング方針

| 場面 | 方針 |
|---|---|
| 情報源単位の失敗 | 1情報源で例外が出ても他情報源の収集を継続。失敗は `CrawlLogs` に記録（status=Failed/PartialError） |
| HTTP リトライ | Polly でリトライ・タイムアウト・サーキットブレーカー。回数/間隔は設定外部化 |
| LLM 失敗 | 構造化失敗時は当該記事をスキップしログに残す（バッチ全体は止めない） |
| 重複登録 | UNIQUE 制約違反は正常系として扱い、当該記事を新規扱いしない |
| 通数上限到達 | 送信を停止し、アプリ内（ダッシュボード）に未通知として表示。ログに理由を記録 |
| ログ方針 | ローカルファイル依存を避け DB（CrawlLogs/NotificationLogs）＋標準出力に寄せる。UTF-8 |
| 認証失敗 | 簡易認証の失敗はログイン画面に留める（VPS移行時に本格化） |

## 9. 制約・遵守事項（全工程で維持）

- **権利**: 記事本文をそのまま保存・表示しない（自作要約＋元URLのみ）。公式画像を自サーバー保存しない。ロゴ/ビジュアルを使わない。robots.txt 尊重。スクレイピング禁止サイトは除外。→ README に明記。
- **コスト**: LLM 呼び出しは収集時の構造化に限定。RSS で取れる情報源を優先。AI コストはユーザー数に比例させない。
- **移行性**: Windows 固有 API 不使用。パスは `Path.Combine`。設定は全外部化。SQLite 不使用。文字コード UTF-8。バッチと Web は別プロセス。
- **冪等性・UTC**: §6・NFR-07/08 の通り。
